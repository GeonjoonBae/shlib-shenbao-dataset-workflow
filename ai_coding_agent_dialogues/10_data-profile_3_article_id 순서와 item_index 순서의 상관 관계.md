# 프롬프트
shenbao\shenbao_textdata\data_profile 경로 안의 `shenbao_textdata_inpageordertest_*.csv`의 데이터를 검토해서, item_index와 article_id의 상관 관계 유무를 검토
# 답변
검토했습니다. 대상 폴더는 data_profile 안의 `shenbao_textdata_inpageordertest_*.csv` 6개 파일입니다.

핵심 결론:
- `item_index`와 `article_id` 사이에 **안정적인 상관관계는 없다고 보는 편이 맞습니다.**
- 더 정확히 말하면, 각 파일 안에서 `item_index`가 커질수록 `article_id`도 일정하게 커지거나 작아지는 **일관된 단조 관계는 없습니다.**
- 일부 파일, 특히 `19370418` 파일에서는 **약한~중간 정도의 양의 경향**이 보이지만, 전체적으로 재현되는 규칙은 아닙니다.
- 따라서 `item_index`만 보고 `article_id`를 예측하거나, 반대로 `article_id`만 보고 기사 순서를 복원하는 것은 어렵습니다.

검토 방법:
- 원본 CSV에는 `article_id` 열이 없어서 `detail_url`의 `id=` 값에서 추출했습니다.
- 예: `...tm_shownews.php?id=A2013010003868...` → `article_id = A2013010003868`

기본 확인:
- 총 6개 파일, 총 669행
- 669행 모두 `article_id`가 추출되었고, **중복 없이 모두 유일**했습니다.
- 즉 이 표본에서는 `item_index 1개 ↔ article_id 1개` 대응은 되지만, **순서상의 규칙성은 약합니다.**

파일별 상관 검토:
- `18870418_1to27`: Pearson `-0.2836`, Spearman `-0.2631`
- `18970418_1to35`: Pearson `-0.2114`, Spearman `-0.1826`
- `19070418_1to103`: Pearson `-0.0056`, Spearman `-0.0151`
- `19170418_1to117`: Pearson `0.0424`, Spearman `0.1852`
- `19270418_1to189`: Pearson `0.0384`, Spearman `0.1674`
- `19370418_1to198`: Pearson `0.3419`, Spearman `0.5271`

해석:
- `1887`, `1897`, `1907`, `1917`, `1927` 파일은 사실상 **상관이 없거나 매우 약합니다.**
- `1937` 파일만 어느 정도 양의 상관이 있지만, 이것도 절대적인 규칙은 아닙니다.

단조성 검토:
인접한 두 행에서 `article_id`가 증가한 비율을 봤습니다.

- `1887`: 53.85%
- `1897`: 47.06%
- `1907`: 61.76%
- `1917`: 62.93%
- `1927`: 61.70%
- `1937`: 71.07%

해석:
- 만약 `item_index`와 `article_id`가 강하게 연결되어 있으면 이 값이 거의 `100%`에 가까워야 합니다.
- 실제로는 감소하는 구간이 계속 섞여 있어서 **순서가 뒤집히는 일이 자주 발생**합니다.

정렬 일치도:
- 각 파일에서 `article_id`를 숫자순으로 정렬했을 때, 그 순위가 원래 `item_index`와 정확히 일치하는 행 수를 봤습니다.
- 결과: 파일당 `0`건 또는 `1`건뿐이었습니다.

즉:
- `item_index = 37`이면 `article_id`도 “37번째로 작은/큰 id”일 것이라는 식의 관계는 거의 없습니다.

중요한 구조적 단서:
후반 파일들은 `article_id` 접두부가 섞여 있습니다.

- `19170418`: `A2013040` 102건 + `A2015100` 15건
- `19270418`: `A2013060` 167건 + `A2015100` 22건
- `19370418`: `A2013061` 139건 + `A2015100` 59건

이건 `article_id`가 원 신문 지면의 순서라기보다,
- 데이터베이스 구축 시기의 내부 처리 단위
- 후속 보정/재탑재 배치
같은 요소를 반영할 가능성이 높다는 뜻입니다.

최종 판단:
- `item_index`는 검색 결과 목록에서의 순서입니다.
- `article_id`는 데이터베이스 내부 개체 식별자입니다.
- 둘은 **1:1 대응은 하지만, 순서상 상관은 약하거나 불안정**합니다.
- 따라서 연구나 전처리에서:
  - **기사 순서 기준**으로는 `item_index`
  - **중복 식별 기준**으로는 `article_id`
  를 따로 쓰는 것이 맞습니다.

한 줄 요약:
- `item_index`와 `article_id` 사이에 실질적인 순서 상관은 없고, `article_id`는 정렬용 순번이라기보다 개체 식별자에 가깝습니다.

원하면 다음으로
1. `item_index`와 `page`의 관계
2. `item_index`와 `date`/`issue_page`의 관계
3. `article_id` 접두부별 분포와 예외 행
도 이어서 정리해드릴 수 있습니다.
